# Reporting materials

## Language and storyline

Use the requested language. Keep the existing brief's language for revisions by default, and otherwise match the user's language. Use short sentences and familiar words. Explain specialist terms where the reader needs them. Start with the change or decision that matters most, give the evidence and its implication, and end with what the reader should do. Use headings that summarize the findings.

## Prepare and verify

Use python-docx to read or deliver editable Word files. Use pypdf for PDF text and page operations and pypdfium2 for rendered page checks.

1. Identify the audience, period, purpose, and decision the materials should support.
2. Tie each conclusion to evidence and give numbers their period, unit, denominator, or comparison cohort when those affect interpretation. Use consistent locale formatting.
3. For a project update, organize the material around progress against milestones, open risks or dependencies, decisions needed, and next actions. Name owners and dates when the sources establish them. Mark missing information as open.
4. Keep observations, interpretations, and proposals easy to recognize. Use a compact comparison table where it helps. Verify important claims against the sources or the shared metrics before delivery.
