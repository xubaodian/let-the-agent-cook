让 Agent 整理一份销售表时，模型可以决定先读文件，再运行脚本。文件路径怎么解析、脚本在哪儿跑、结果如何交付，由运行时负责。

## 一个调用怎样走完

1. **模型给出调用意图。** 请求中的工具定义告诉模型有哪些工具、分别接收什么参数。模型返回工具名、参数和调用 ID。
2. **运行时执行。** Agent Cook 用注册表找到工具，再用该任务的工作区读文件或执行脚本。执行边界、超时和参数检查都在这一步生效。
3. **结果写回对话。** 运行时用调用 ID 将结果和原请求关联，作为一条工具消息加入上下文。下一轮模型就能根据结果继续处理。
4. **交付前再检查。** 模型可以提交工作区里的文件。运行时记录提交版本，结束前再次核对文件是否变化。发生变化时，模型需要重新检查并提交。

## Tool Call 和 MCP 在哪儿碰面？

Tool Call 描述模型想调用哪个工具。MCP 描述运行时怎样发现和调用外部服务上的工具。模型在同一份工具列表中能看到本地的 **read_file**，以及由 MCP 接入的 **fixture-data/query_rows**。前者读取工作区，后者经 MCP 连接数据服务。工具响应仍通过同一条 Agent 循环写回上下文。

周报案例里的两页订单、口径文档、浏览器筛选和最终提交，都沿着这条链路执行。跟着回放看每一步，就能找到这些工具产出的具体文件。
